⚡ Semantic Cache Application

A caching layer for LLM applications that recognizes when two queries mean the same thing — even when the words, the modality, or both are different. Paraphrased text, near-duplicate images and spoken questions all reuse a previously generated response instead of paying for another API call.

# overview

why this exists, and what it actually does

problem.md

LLM apps get asked the same question a hundred different ways — "how do I reset my password" vs "I forgot my password, how do I change it". Exact-match caching never fires on the paraphrase, so every rewording pays full LLM latency and cost again.

And it's not just text anymore — the same problem shows up for near-duplicate images and spoken questions that get transcribed differently every time.

solution.md

Embed the query, search a FAISS vector index for something semantically close enough, and return the cached response in under 10ms on a hit — falling back to the real LLM only on a genuine miss.

Hybrid BM25 retrieval rescues exact keyword matches vector similarity blurs, eviction keeps the cache from growing forever, and the same machinery extends to CLIP-embedded images and Whisper-transcribed audio.

# query_lifecycle

what happens between submitting a query and getting a response

or click any step

Query embedded

Text goes through Embedder (Sentence-Transformers), images through ImageEmbedder (CLIP), producing an L2-normalized vector. Audio is transcribed to text first via AudioTranscriber and re-enters this same step as a text query.

FAISS similarity search

The vector is compared against every cached entry in an IndexFlatIP index. With L2-normalized vectors, inner product equals cosine similarity — no separate normalization step needed at query time.

Hybrid rescoring (optional)

If hybrid mode is on, a parallel BM25Okapi keyword search runs over the same cached queries, and the two scores blend as hybrid = vector_weight·cosine + bm25_weight·bm25_norm — rescuing exact keyword matches the embedding blurred.

Threshold check

The best-scoring candidate is accepted as a HIT only if it clears SIMILARITY_THRESHOLD (or HYBRID_SIMILARITY_THRESHOLD in hybrid mode) — otherwise it's a MISS, and generation is required.

HIT → instant return

A hit reads the cached response straight from in-memory metadata — no model call, no network round trip. This is the <10ms path, and it also marks the entry as just-used for LRU.

MISS → generate + cache

A miss calls LLMClient.generate() (text) or generate_vision() (image, base64-encoded or URL), then SemanticCache.put() stores the new pair — triggering TTL/LRU eviction checks before the write completes.

Logged & visualized

Every request — hit or miss, whichever modality — is written to SQLite via RequestLogger with a modality label, then rendered live in the Streamlit dashboard's KPIs, charts and log table.

# what_it_does

the feature set, honestly summarised

⚡

Sub-10ms cache hits

A HIT reads straight from the in-memory FAISS index and metadata — no model call, no network round trip.

🔀

Hybrid vector + BM25 search

Blends cosine similarity with keyword scoring so exact terms, IDs and acronyms aren't lost to embedding drift.

🧹

TTL + LRU eviction

Age-based expiry and a least-recently-accessed capacity cap, both off by default and rebuilt from stored FAISS vectors — no re-embedding needed.

🖼️

Image caching (CLIP)

Images get their own 512-d vector space and index, matched by visual similarity, independent of the text cache.

🎤

Audio caching (Whisper)

Audio is transcribed to text and reuses the exact same text cache — no separate audio vector space to maintain.

📊

Live analytics dashboard

Streamlit dashboard with hit-rate, latency, cost-saved KPIs, request logs and a raw cache inspector.

🗄️

SQLite request logging

Every request logged with modality, latency and hit/miss — schema self-migrates for older DB files.

🧪

72 automated tests

Deterministic fake embedders and mocked LLM/API calls — no real network access required to verify correctness.

⚙️

CI/CD pipeline

GitHub Actions runs flake8 and the full pytest suite on every push.

# engineering_notes

decisions worth defending in an interview

Eviction rebuilds, never re-embeds

TTL/LRU pruning rebuilds the FAISS index directly from its own stored vectors (reconstruct_n), so removing entries never calls the embedding model — pruning stays cheap regardless of corpus size.

LRU touches stay in memory

last_accessed_at updates on every cache HIT, but only in memory — never triggering disk I/O on the hot path. Persistence happens on the next write, keeping hit latency under 10ms.

Hybrid is opt-in by design

ENABLE_HYBRID_SEARCH defaults to false, so existing vector-only deployments and their similarity thresholds behave identically unless a caller explicitly opts in.

Images and text never share a space

CLIP's 512-d image embeddings and MiniLM's 384-d text embeddings aren't comparable, so image queries always get their own FAISS index — never a cross-modal lookup that would silently return nonsense.

Audio reuses the text cache on purpose

Rather than build a third vector space, an audio query is transcribed and dropped straight into the existing text pipeline — two spoken queries that mean the same thing become the same cache problem the project already solves.

Everything is testable without a network

Deterministic fake embedders (orthonormal basis vectors) and mocked OpenAI clients mean all 72 tests run without real model downloads or API calls — CI has no OPENAI_API_KEY secret, and doesn't need one.
